= Flujo de trabajo de Google Cloud NetApp Volumes para implementar Oracle Database 26ai de alta disponibilidad
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
Utiliza el almacenamiento en bloques iSCSI de Google Cloud NetApp Volumes para implementar alta disponibilidad de Oracle Database 26ai con Oracle Data Guard en Google Compute Engine. Este flujo de trabajo te guía por las opciones de implementación, el aprovisionamiento de infraestructura, la instalación del software de Oracle y la configuración de alta disponibilidad, aprovechando la replicación en la capa de almacenamiento de GCNV para acelerar la inicialización del sistema en espera.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-1.png["1"]link:gcnv-oracle-solution-architecture.html["Revisa la arquitectura de la solución"]
[role="quick-margin-para"]
Conoce la arquitectura de Google Cloud NetApp Volumes para la alta disponibilidad de Oracle Database 26ai, incluyendo el diseño de almacenamiento en bloques iSCSI de GCNV, la integración con Data Guard y la topología de almacenamiento.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-2.png["Dos"]link:gcnv-oracle-deployment-options.html["Revisa las opciones y los requisitos de implementación"]
[role="quick-margin-para"]
Compara los niveles de implementación, desde desarrollo y pruebas hasta producción con alta disponibilidad (HA), y confirma los requisitos previos de infraestructura, acceso y software.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-3.png["Tres"]link:gcnv-oracle-access-and-apis.html["Verifica el acceso y las API"]
[role="quick-margin-para"]
Confirma los requisitos de acceso necesarios, la activación de la API, los requisitos previos de red y la sincronización horaria.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-4.png["Cuatro"]link:gcnv-oracle-provision-compute.html["Aprovisiona instancias de Google Compute Engine"]
[role="quick-margin-para"]
Crea máquinas virtuales para la base de datos principal, la base de datos de reserva y el observador Fast-Start Failover.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-5.png["Cinco"]link:gcnv-oracle-provision-storage.html["Provisiona almacenamiento iSCSI de GCNV"]
[role="quick-margin-para"]
Crea grupos de almacenamiento GCNV y volúmenes iSCSI, configura multivía y configura grupos de discos ASM.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-6.png["Seis"]link:gcnv-oracle-install-software.html["Instalar Oracle Grid Infrastructure y Oracle Database 26ai"]
[role="quick-margin-para"]
Instala el software Oracle Grid Infrastructure y Oracle Database 26ai en ambos hosts de base de datos.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-7.png["Siete"]link:gcnv-oracle-primary-database.html["Crear la base de datos principal"]
[role="quick-margin-para"]
Crea la base de datos Oracle principal con almacenamiento ASM y configura Oracle Restart.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-8.png["Ocho"]link:gcnv-oracle-standby-database.html["Crear la base de datos de reserva"]
[role="quick-margin-para"]
Inicializa la base de datos en espera usando la replicación GCNV, instantáneas o clones, y luego regístrala con Oracle Restart. Todos los niveles de alta disponibilidad completan este paso.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-9.png["Nueve"]link:gcnv-oracle-standby-finalize-dg.html["Finaliza la base de datos en espera para Data Guard"]
[role="quick-margin-para"]
Crear registros de recuperación en espera, habilitar flashback, activar el trasvase de registros de recuperación y verificar el estado de Data Guard. *Específico del nivel:* solo es obligatorio para el nivel Prod HA (Data Guard + FSFO).

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-10.png["Diez"]link:gcnv-oracle-data-guard.html["Configura Data Guard Broker y la conmutación por error de inicio rápido"]
[role="quick-margin-para"]
Activa el broker, crea la configuración de Data Guard, activa FSFO y configura el Observer. *Específico del nivel:* solo es necesario para el nivel Prod HA (Data Guard + FSFO).
